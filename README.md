# Research Pivot · 论文研究搭档

用文献证据逐步推进选题、贡献定位、实验与写作的 AI 技能。

Research Pivot 帮你把一个模糊的研究想法拆成可以讨论、检索和验证的问题，在已有工作的基础上梳理潜在贡献，并保留研究进度、证据与决策。默认使用中文，每次聚焦一个有意义的下一步。

> 本项目是借鉴 LitPivot 研究机制的独立技能实现，与 Ai2 无隶属关系。它提供研究协作流程，创新性和论文录用仍需实际研究与同行评审验证。

## 适合什么时候用

- 有初步想法，希望明确研究问题、候选贡献和评估方案。
- 找到几篇相关论文，需要比较它们与自己工作的重合和差异。
- 担心已有工作覆盖了自己的贡献，需要有证据地判断是否调整方向。
- 准备实验，需要梳理基线、对照、指标和可证伪条件。
- 实验结果出来了，需要区分观测事实、解释和后续验证。
- 开始写论文，需要核对论点与引用是否有实际证据支撑。
- 中断一段时间后继续研究，希望从已保存的档案恢复进度。

## 核心能力

| 能力 | 做什么 |
| --- | --- |
| 研究想法拆解 | 按问题（P）、贡献（C）、评估（E）拆分想法，识别缺失环节 |
| 文献检索与证据整理 | 分面检索、去重、扩展相关引用，记录来源位置与访问情况 |
| 分面聚类与比较 | 分别从研究问题、贡献机制、评估设计组织论文，供研究者选择 |
| 贡献—局限分析 | 将已有贡献、局限与未来工作关联起来，检查候选贡献的依据 |
| 修改建议与决策记录 | 给出批评、证据、建议改写与取舍，区分待确认和已接受内容 |
| 修改联动检查 | 想法变化后标记受影响的检索、论点与实验，提醒重新核对 |
| 实验与写作辅助 | 将主张映射到实验设计，保留负面结果，审查写作中的强断言 |

分析结论限定于实际读过的文献。仅能访问摘要或无法获取全文时，会明确标记；文献中的局限也需要检查是否已被后续工作解决。

## 安装

### 在 Codex 中安装

把下面这句话发给 Codex：

```text
请使用 skill-installer 安装这个仓库的技能：
https://github.com/dmety/research-pivot-skill
技能位于仓库根目录，安装名称使用 research-pivot。
```

### 手动安装到本地 Codex

将整个仓库克隆到技能目录，保留根目录的 `SKILL.md` 和配套文件。

macOS / Linux：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/dmety/research-pivot-skill.git ~/.codex/skills/research-pivot
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.codex\skills" | Out-Null
git clone https://github.com/dmety/research-pivot-skill.git "$env:USERPROFILE\.codex\skills\research-pivot"
```

如果设置了 `CODEX_HOME`，请使用其下的 `skills/research-pivot` 目录。目标目录已存在时，先检查已有安装，避免覆盖本地修改。

这是由 Markdown 指令、参考文件和界面配置组成的技能仓库，没有单独的应用服务或依赖安装步骤。文献检索、PDF 阅读和文件保存依赖宿主环境提供的工具与权限。

## 快速开始

安装后，在对话中明确调用技能，并提供当前想法或已有材料：

```text
使用 $research-pivot 帮我推进一个论文选题。
我的初步想法是：……
目前已有的论文或材料是：……
先找出最需要澄清的问题，并引导我完成下一步。
```

不需要一次填写完整表格，可以从一段想法、一篇论文或一份实验结果开始。

### 常用提示词

**继续已有研究**

```text
使用 $research-pivot 继续我的论文。
研究档案位于：……
请读取最新状态和决策记录，告诉我当前阶段与下一步。
```

**比较新论文**

```text
使用 $research-pivot 比较这篇新论文与我的候选贡献：……
论文链接或文件：……
请检查问题、方法和评估的重合，并说明哪些结论需要重新核对。
```

**检查候选创新**

```text
使用 $research-pivot 检查这个候选贡献：……
先整理最接近和可能反驳它的工作，给出初步比较，
等我确认文献范围后再进行正式评估。
```

**分析实验结果**

```text
使用 $research-pivot 分析这组实验结果。
假设与实验设计：……
日志、配置和结果文件：……
请区分观察、解释与尚需验证的部分，并保留负面结果。
```

## 如何推进研究

1. **明确想法**：拆分 P / C / E，区分事实、假设和候选贡献。
2. **查找相关工作**：检索原始论文，记录查询范围、来源与证据位置。
3. **选择比较范围**：按不同分面组织论文，由研究者确认正式评估所用文献。
4. **评估与改写**：检查问题依据、贡献重合和评估可行性，提出带证据的修改建议。
5. **记录决策**：由研究者接受、编辑或拒绝建议，保存版本与理由。
6. **推进验证**：设计实验、解释结果、核查写作；修改后检查受影响的论点与证据。

默认每次输出当前阶段、至多三条有证据的发现、一个下一步行动，以及必要时的一项待决策问题。详细证据和长表格保存在项目记录中。

## 研究档案与隐私

每篇研究应使用独立的私有目录，放在本技能仓库之外。保存前先明确存储位置；能够保存时，按 [研究档案约定](references/state.md) 维护 `state.json`，必要时将长证据和历史记录拆分到关联的 Markdown 文件。

记录内容包括：

- 当前阶段、想法版本、下一步行动。
- P / C / E 主张、论文清单、检索记录与证据位置。
- 文献聚类、已选择的论文与贡献—局限关系。
- 修改提案、研究者决策、实验设计及待复核事项。

待确认建议与已接受内容分开记录。跨环境迁移需要显式传输，不提供自动同步；无法保存时，会在对话中说明并提供交接信息。请勿把未发表论文、研究档案、个人信息或凭据提交到公开技能仓库。

## 能力边界

- “当前文献集合中存在空白”只代表这个检索范围内的发现，不能直接证明创新性。
- 不提供通用的“创新分数”，不编造引用、实验结果、统计显著性或录用承诺。
- 不预置 Asta Paper Finder 或 Semantic Scholar API 集成，不复现 LitPivot 的界面、模型组合或排名结果。
- 检索与全文获取受宿主工具、权限和来源可访问性影响，缺失材料会明确标记。
- 昂贵实验、依赖安装、预注册变更、未发表材料上传与发布，需要相应授权。
- 实验和写作辅助是本技能的扩展；研究方向与关键决策由研究者确认。
